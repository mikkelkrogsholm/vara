# Runtime and native localization verification

The desktop host returns the canonical `vara-core/messages/runtime.json` via the
read-only `runtime_catalog` action. The browser formats versioned messages and
safe nested causes at the presentation boundary. Host-owned failures use stable
codes; captured IO and JSON causes carry only their typed or numeric details.
Unknown external strings receive a localized summary and retain only numeric
HTTP/OS codes or a narrow allowlist of safe technical classes. Arbitrary legacy
text is withheld because it can contain secret values, paths or user content.
There is no translation based on matching Danish source strings.

The browser test uses the actual catalog and an in-memory host. It covers runtime
snapshot/status, nested causes, dialog errors, Who errors, a redacted unknown,
locale changes with retained editor/focus/selection, the reserved unknown-app
presentation, persisted raw app names and a startup failure. Existing main,
locale, transcription and legacy regression fixtures also run against isolated
hosts. Native AppKit exercises the actual `macos_hud.m`: da/en labels and
accessible descriptions, panel identity/nonactivation, callbacks, recording and
processing states, and PNG rendering. The Foundation fixture copies the exact
configured bundle file mappings, parses the resources with `plutil`, and checks
`NSBundle.localizedInfoDictionary` in separate language processes. Its English
development region matches the value generated by tauri-bundler 2.10.4. A
separate `test-harness` entry constructs the actual Tauri tray menu, checks
stable menu handles and AppKit tooltip across locale changes, and opens the
actual RFD open/save panels in an empty temporary directory. An in-process AppKit
callback checks and cancels those panels. RFD's macOS backend uses the filter
extension but does not display the supplied filter name; the localized label is
still passed to RFD for platforms that use it. No microphone, TCC prompt,
personal profile, key or model is touched.

Commands (set `PLAYWRIGHT_MODULE` and `PLAYWRIGHT_CHROMIUM` to local installs):

```sh
cargo test -p vara-core --target-dir /tmp/vara-i19-target
cargo test -p vara-desktop --lib --target-dir /tmp/vara-i19-target
cargo check --manifest-path desktop/src-tauri/Cargo.toml --target-dir /tmp/vara-i19-target
cargo build -p vara-desktop --bin vara-desktop --features test-harness --target-dir /tmp/vara-i19-target
VARA_TEST_NATIVE_LOCALIZATION=1 /tmp/vara-i19-target/debug/vara-desktop
node desktop/tests/i18n.test.cjs
node desktop/tests/runtime-messages.test.cjs
node desktop/tests/ui-main-i18n.playwright.cjs
node desktop/tests/ui-locale.playwright.cjs
node desktop/tests/transcription-i18n.playwright.cjs
node desktop/tests/runtime-i18n.playwright.cjs
node desktop/tests/legacy-runner.cjs
VARA_DESIGN_HEADER_DIR="$(dirname "$(find /tmp/vara-i19-target/debug/build -name vara_design.h | head -1)")" desktop/tests/native-localization.sh
```

The HUD PNGs and fixture bundle are written under `/tmp/vara-22b-native`; browser
screenshots default to `/tmp/vara-22b-screens`. The test exercises actual AppKit
HUD and Foundation localization in isolation, not the installed app or a real
permission prompt. The menu and RFD fixture is compiled only with the existing
`test-harness` feature and does not initialize the service, shortcuts or app
profile. Windows/Linux native behavior remains untested. The fixture bundle
verifies the actual mapping and Foundation lookup but is not a complete
production bundle.
