# macOS CLI packaging and local inference — 2026-11-04

The normal app was built and installed after checking that the prior app had no
active work. The actual command, from the repository root, was:

```sh
PATH="$HOME/.cargo/bin:$PATH" DEVELOPER_DIR=/Library/Developer/CommandLineTools \
CARGO_NET_OFFLINE=true CARGO_INCREMENTAL=0 CARGO_PROFILE_RELEASE_DEBUG=0 \
sh scripts/build-desktop-macos.sh > /tmp/vara29-migration-build.log 2>&1
```

The script passes `--locked` to Cargo. Swift fetched the pinned SDK revision on
the first build and resolved its dependency from cache; Cargo used offline mode.
The signed installed bundle verifies as `dk.vara.desktop`, team `3B7KHK6C9K`;
`~/.local/bin/vara --version` returned `vara 0.1.0`. The installed executable
SHA-256 was `1642c18884fe03e8caa3529796898128c490a8dd0207a7e24cf44ae9b8cdcb1d`.
The bundle is Developer ID signed and is not notarized.

`python3 scripts/tests/vara_launcher.py` passed missing-app JSON, old-app JSON,
and argument forwarding checks. Running the launcher against the previously
installed old app also returned `cli.app_incompatible`, exit 5, without starting
it. The signed app includes the launcher, protocol marker, CLI guide and Who
runtime. The installed launcher starts the same signed desktop executable.

The real inference command used an isolated profile, the installed launcher and
pre-existing local Redux and Who weights:

```sh
python3 scripts/tests/real_local_cli.py /Applications/Vara.app \
  "$HOME/Library/Application Support/dk.vara.desktop/models" \
  /tmp/vara29-real-final "$HOME/.local/bin/vara" > /tmp/vara29-real-final.log 2>&1
```

It did not use test-harness replay, personal audio or cloud models.
The inputs are made from the repository's 10.312-second `Samples/da_test.wav`,
repeated to span the Who window, plus a synthetic video and short Sara voice.
Results on this machine:

- Audio, 319.676 s, known count 1: real ASR and Who completed, with one raw
  SDK turn and 89 bounded consensus intervals.
- Video, 92.928 s, automatic Who: real ASR and Who completed with two SDK turns.
- Short synthetic audio, 5.854 s, known count 1: no SDK turns; honest
  `file.who_unclear`, with ASR retained.
- Repeated sample, 92.809 s, known count 1: `who.known_count` because the
  single piece cannot supply the required cross-piece evidence, with ASR retained.

These are execution and persistence checks, not speaker-accuracy measurements.
The SDK patch was tested by migrating an existing prior-patched checkout and
verifying that the new patch is already applied on a subsequent check. The release test passed with:

```sh
PATH="$HOME/.cargo/bin:$PATH" DEVELOPER_DIR=/Library/Developer/CommandLineTools \
CARGO_NET_OFFLINE=true CARGO_INCREMENTAL=0 CARGO_PROFILE_RELEASE_DEBUG=0 \
cargo test --release --locked -p vara-engine who_known::tests::single_piece_cannot_establish_known_count
```

Its log is `/tmp/vara29-known-test.log`. The local smoke log and retained fixture
are `/tmp/vara29-real-final.log` and `/tmp/vara29-real-final/`. Earlier process
regression evidence `/tmp/vara28-repair-cli.log` used an explicitly marked
`test-harness` build and synthetic replay; it does not demonstrate real inference.

Native playback/editing could not be inspected because the Mac remained locked.
MAIN separately reported browser UI and localization suites passing; this does not
substitute for native playback and editing. No Windows/Linux package,
cloud inference, notarization or multi-speaker accuracy was tested here.
