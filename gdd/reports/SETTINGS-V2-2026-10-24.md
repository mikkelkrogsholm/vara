# Settings v2 — 2026-10-24

Implemented the three approved settings mockups in the native desktop app, and
updated DESIGN.md §18/§19. This is a UI/configuration-flow change; shared Rust
domain behavior, credentials, inference and delivery remain unchanged.

## Organization and components

- Diktering: recording controls, speech model, optional text AI/model/instructions,
  app-rule link and existing native permissions. Direct transcription remains the
  default; saved user selections are not replaced by illustrative mockup values.
- Modeller og nøgler: local download/verification/cancellation/progress, key status
  and tests, all existing providers, custom endpoints/model names and CLI checks.
- Privatliv: strict on-device rule, default processing destinations, positive
  retention periods (including custom values), and fixed audio policy explanations.
- Shared `settingsSection` (editorial grid/full-width variants), `modelSelect` and
  `modelLabel`, native `processingChoice`, and `policyRow`. Model feedback is reused
  by speech, global text and per-app text selection. Shared provider/download rows
  retain their existing commands and status semantics.
- Conditional controls retain their values. Saving reads the fields on the active
  page into a clone of existing settings, preserving unrelated preferences, custom
  engine configurations and app rules. No migration is needed.
- Model setup works in context. Key dialogs, download events and CLI checks preserve
  unsaved form edits. Textarea blur does not replace contextual action buttons.
- AI pr. app retains overrides and standard inheritance. First-use cloud preference
  reaches the speech selector directly. Native shortcuts retain their full range.

## Evidence

- Production UI harness: all **23 groups pass**, including previous history,
  shortcut, permission, key status/test and responsive checks. New flows exercise
  both model choices saved together, native radio keyboard behavior, hiding/revealing
  AI fields without data loss, language switching, contextual key setup, local
  download/cancellation/progress, strict locality and per-app overrides.
- Three new settings surfaces checked at widths 1586, 1040, 720 and 320 CSS px,
  including internal content overflow checks. Existing histories/settings/apps
  continue to pass the older intermediate-width checks.
- Signed Mac application build passes deep/strict signature and microphone
  entitlement checks. Native app reopened; all three pages visually inspected.
  Actual saved OpenAI speech selection, direct-text mode, key presence, history
  retention and permission grants remained visible. No actual user preference,
  credential or history item was changed during native inspection.
- DESIGN.md linter **@google/design.md 0.4.0**: 0 errors, 4 existing orphan-token
  warnings. The four colors are intentionally used in CSS/prose (brand waveform,
  focus rings, inverse focus and inverse success); no duplicate token usage was
  invented to silence the linter. No color/token exports changed.
- GDD model/record integrity and generated graph validated. Broader implementation
  acceptance plans remain UNKNOWN; these results do not assert full release
  readiness or Windows/Linux native verification.
- No new speech/text inference, live API test or microphone capture was performed;
  those backend paths were unchanged. UI fixtures use fictional API keys.
